# DIAGNOSIS
###############################################################################

WHAT THIS RUN PROVES
  * Real dual-XPU host: Ray detected 2 XPUs and assigned two DIFFERENT physical
    devices to the two concurrent actors - get_gpu_ids() = [1] and [0]
    (order is just Ray's scheduling; both devices covered, no collision).
  * Platform resolves to XPUPlatform with device_control_env_var = 'ZE_AFFINITY_MASK'
    on real Intel hardware, via vLLM's abstraction (no vendor if/else in OpenRLHF).
  * backend='ray' branch clears the inherited visibility pin (env AFTER = none set)
    so vLLM's own ray executor can assign devices to its child workers.

WHAT THIS RUN DOES *NOT* PROVE (important)
  * ray_noset_visible_devices() = False in this run, so the elif branch did NOT
    execute - i.e. ZE_AFFINITY_MASK was NOT set by OpenRLHF here. In the mp case
    env AFTER just shows the CUDA_VISIBLE_DEVICES that Ray itself set.
  * On XPU, vLLM reads ZE_AFFINITY_MASK, NOT CUDA_VISIBLE_DEVICES. So with
    noset=False, Ray's CUDA_VISIBLE_DEVICES pin is not the variable vLLM honors -
    which is exactly the gap the fix closes when noset=True.

TO PROVE THE FIX ITSELF ON THIS BOX (elif branch sets ZE_AFFINITY_MASK)
    export RAY_EXPERIMENTAL_NOSET_CUDA_VISIBLE_DEVICES=1
    export RAY_EXPERIMENTAL_NOSET_ONEAPI_DEVICE_SELECTOR=1
    ray start --head --num-gpus=2
    python tools/prove_device_pinning_realray.py
  Expected: ray_noset_visible_devices()=True, and env AFTER (backend='mp') shows
  ZE_AFFINITY_MASK set to each actor's distinct id (0 and 1).
